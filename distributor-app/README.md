# تطبيق الموزعين — الكيف الأصلي

تطبيق أندرويد (Flutter) للمبيعات الميدانية من مخزون السيارة. **يعمل بدون إنترنت**، ويزامن مع نظام الكيف الأصلي عند توفر الشبكة.

## ماذا يفعل
- **العملاء**: عملاء الموزع، مع الرصيد المستحق والحد الائتماني والمتاح، وتنبيه للعملاء المتأخرين.
- **البيع**: من مخزون السيارة بأسعار العميل، نقداً أو آجلاً أو جزئياً، مع تطبيق الحد الائتماني وأيام التأخير بنفس قواعد النظام.
- **التحصيل**: سند قبض عن فاتورة محددة أو عن الأقدم تلقائياً.
- **المرتجعات**: إشعار دائن مع سبب الإرجاع والفاتورة الأصلية. البضاعة تعود لمخزون السيارة، والمبلغ يُخصم من رصيد العميل أو يُرد له نقداً.
- **خط السير والزيارات**: عملاء اليوم حسب أيام الزيارة والترتيب، مع علامة لمن تمت زيارته. كل بيع أو تحصيل أو مرتجع يُسجَّل زيارةً بموقع GPS، ويمكن تسجيل "زيارة بدون بيع" مع السبب (مغلق، لا يحتاج، لا سيولة...).
- **إقفال اليوم**: ملخص اليوم، والنقد المتوقع في العهدة، وجرد مخزون السيارة، والنقد المسلَّم مع إظهار العجز أو الزيادة، وتقرير مطبوع للتوقيع.
- **الأمان**: كلمة المرور محفوظة مشفّرة في الجوال (Android Keystore).
- **الطباعة**: فاتورة ضريبية مبسطة أو ضريبية مع رمز QR الخاص بهيئة الزكاة، أو سند قبض، على طابعة بلوتوث حرارية (80 أو 58 مم). تُطبع كصورة فيظهر النص العربي سليماً على أي طابعة ESC/POS.
- **المزامنة**: ترفع المستندات (مرة واحدة فقط لكل مستند)، ثم تحمّل بيانات محدثة: العملاء، الأرصدة، المخزون، الأسعار.

الترقيم على الجوال متسلسل ولا يتكرر:
- الفواتير: `D01-000001`.
- سندات القبض: `D01-R-000001`.
- المرتجعات: `D01-C-000001`.
- إقفال اليوم: `D01-Z-000001`.

## الإعداد في النظام
1. **الفوترة ← الإعدادات ← التوزيع**:
   - اختر نوع فاتورة الموزعين، ويجب أن يكون فيه نوع شحنة مع "إنشاء شحنة تلقائياً".
   - اختر نوعَي الدفع: نقداً، وتحويل أو بطاقة.
   - اختر نوع المرتجع للموزعين: نوع فاتورة مورد معلَّم كمرتجع، فيه نوع استلام مع "إنشاء استلام تلقائياً".
   - اختر نوع دفعة الاسترداد النقدي.
2. أنشئ **موقع مخزون** لكل سيارة، وحمّل البضاعة إليه بتحويل مخزني من المستودع.
3. في **بطاقة الموظف ← التوزيع**:
   - فعّل "الموزع".
   - اختر موقع السيارة.
   - حدد بادئة مستندات فريدة، مثل `D01`.
   - اربط حساب الصندوق بالموظف.
4. في **بطاقة كل عميل ← المبيعات ← خط السير**:
   - اختر الموزع.
   - حدد أيام الزيارة والترتيب.
   - حدد الحد الائتماني.
5. في **الفوترة ← العمليات**: تجد **الزيارات** و**إقفالات اليوم** لمراجعة المحاسب.
6. يدخل الموزع في التطبيق بعنوان الخادم واسم مستخدمه وكلمة مروره.

## البناء التلقائي على GitHub
- **مع كل تحديث للتطبيق:** يفحص GitHub الكود ويشغّل الاختبارات ويبني ملف APK.
  - **التحميل:** صفحة المستودع ← **Actions** ← **Distributor app** ← آخر تشغيل ← **Artifacts**.
- **إصدار رسمي:** أنشئ وسماً باسم الإصدار، مثل `app-v1.1.0`. يُنشأ **Release** والملف مرفق به، ورقم الإصدار يكون 1.1.0.
- **بناء يدوي:** Actions ← Distributor app ← **Run workflow**.

### مفتاح التوقيع
مفتاح التوقيع **ضروري** لأمرين: تحديث التطبيق على الجوالات بدون حذفه، والنشر على Google Play.
- **بدون المفتاح:** يُوقَّع الملف بمفتاح تجريبي، وهذا يكفي للتجربة فقط.
- **إنشاء المفتاح:** مرة واحدة فقط. **احتفظ بنسخة منه، وبكلمات مروره، في مكان آمن.** إذا ضاع لا يمكن تحديث التطبيق المثبّت.
```
keytool -genkey -v -keystore alkaif-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias alkaif
base64 -w0 alkaif-upload.jks > alkaif-upload.b64
```
- **إضافة المفتاح إلى GitHub:** في Settings ← Secrets and variables ← Actions، أضف:
  - `ANDROID_KEYSTORE_BASE64`: محتوى الملف `alkaif-upload.b64`.
  - `ANDROID_KEYSTORE_PASSWORD`.
  - `ANDROID_KEY_ALIAS`: القيمة `alkaif`.
  - `ANDROID_KEY_PASSWORD`.

## البناء على جهاز
```
flutter pub get
flutter test
flutter build apk --release
```
يحتاج البناء إلى Android SDK. ينتج الملف `build/app/outputs/flutter-apk/app-release.apk`.

يُفضّل أن يعمل الخادم على `https`.
